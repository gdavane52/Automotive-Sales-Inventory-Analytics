# Automotive Sales & Inventory Analytics

Natural-language analytics for automotive dealership data. A user asks a question in plain English; the app checks that the question is in domain, generates read-only SQLite, validates it, runs it, and returns an LLM answer, a Plotly chart, and short business insights in Streamlit.

## Business problem

Dealership teams need answers about stock, sales, digital checkout, and trade-ins without writing SQL. Ad-hoc questions (top models in a city, inventory pressure, checkout activity, trade-in value) usually require an analyst and a spreadsheet.

## Project objective

**Natural language question → domain validation → SQL generation → SQL validation → SQLite execution → DataFrame → LLM answer → Plotly chart → business insight → Streamlit UI**

The design stays simple: one SQLite database, one LangGraph workflow, one Streamlit page. No extra orchestration frameworks.

## Features

- Automotive domain check before any SQL is generated
- Schema-aware SQLite generation (SELECT / WITH only)
- SQL validation (read-only, syntax, known tables/columns)
- Up to 3 SQL generation retries on validation failure
- Read-only SQLite execution with timeout and row cap
- Concise business answer from the result table
- Deterministic Plotly chart (bar, line, or pie) when the table supports it
- 1–3 business insights
- Streamlit UI with example questions and token streaming for answer/insights
- Guardrails: no writes/DDL, no stack traces or API keys in the UI, secret redaction in logs

## Architecture

```
Streamlit (app.py)
        │  stream_analytics_question()
        ▼
LangGraph workflow (src/langgraph)
        │
        ├─ agents: scope, SQL, answer, insight (LangChain + OpenAI)
        ├─ db: schema, guard, validate, execute (SQLite + pandas)
        └─ charts: Plotly figure from the DataFrame (no LLM)
```

Presentation stays in `app.py`. The graph owns the pipeline. `src/db` is the only place that talks to SQLite. Charts never call the LLM.

## Dataset description

Synthetic CSVs in `data/raw/` (generated by `data/generate_data.py`, seed 42), loaded into `data/db/automotive.db`.

| Table | Rows | Grain |
| --- | ---: | --- |
| `vehicle_stock` | 5,000 | One listed vehicle |
| `digital_checkout` | 10,000 | One checkout journey |
| `sales` | 5,000 | One completed sale |
| `trade_in` | 2,500 | One trade-in on a sale |

Locations include Pune, Mumbai, Bengaluru, Delhi, Hyderabad, Chennai, Ahmedabad, and Gurgaon. Dates span 2025–2026.

## SQLite schema

```
vehicle_stock (vehicle_id PK)
    brand, model, variant, fuel_type, location, dealer_id,
    stock_date, stock_status, listed_price

digital_checkout (checkout_id PK)
    customer_id, vehicle_id → vehicle_stock.vehicle_id,
    checkout_date, brand, model, location,
    checkout_stage, checkout_status, channel

sales (sale_id PK)
    customer_id, vehicle_id → vehicle_stock.vehicle_id (unique),
    sale_date, brand, model, location, dealer_id,
    selling_price, trade_in_used

trade_in (trade_in_id PK)
    customer_id, new_vehicle_id → vehicle_stock.vehicle_id,
    trade_in_date, trade_in_brand, trade_in_model,
    trade_in_year, trade_in_mileage, trade_in_value, location
```

Relationships: checkout and sales attach to stock by `vehicle_id`. Trade-ins attach to the new vehicle (`new_vehicle_id`) and the selling customer.

## LangGraph workflow

```
START
  → validate_question
        ├─ in scope     → generate_sql
        └─ out of scope → END
  → generate_sql
  → validate_sql
        ├─ valid                         → execute_sql
        ├─ invalid, attempts < 3         → generate_sql
        └─ invalid, attempts ≥ 3         → validation_failed → END
  → execute_sql
  → generate_answer
  → generate_chart
  → generate_insight
  → END
```

Shared state (`AnalyticsState`) holds the question, scope flag, schema, SQL, validation fields, DataFrame (`query_result`), answer, chart, insights, and `retry_count`.

Recursion is capped (`LANGGRAPH_RECURSION_LIMIT`, default 16) so a bad loop cannot run forever.

## Example questions

- Which are the top 10 selling car models in Pune in 2026?
- Which models have the highest inventory in Pune?
- Which brands have the highest trade-in activity?
- What is the average trade-in value by brand?
- Which models have the highest checkout activity?

Out of scope (rejected before SQL): weather, movies, generic “sales of phones”, requests to DELETE/UPDATE data.

## Example output

Question: *Which are the top 10 selling car models in Pune in 2026?*

Typical SQL:

```sql
SELECT model, COUNT(*) AS sales_count
FROM sales
WHERE location = 'Pune'
  AND strftime('%Y', sale_date) = '2026'
GROUP BY model
ORDER BY sales_count DESC
LIMIT 10;
```

## Environment setup

Copy `.env.example` to `.env` and set the OpenAI key:

```bash
copy .env.example .env   # Windows
# cp .env.example .env   # macOS / Linux
```

| Variable | Default | Purpose |
| --- | --- | --- |
| `OPENAI_API_KEY` | *(required)* | OpenAI API key (never committed or logged) |
| `OPENAI_MODEL` | `gpt-4o-mini` | Chat model |
| `SQLITE_DB_PATH` | `data/db/automotive.db` | Database file |
| `SQL_QUERY_TIMEOUT_SECONDS` | `30` | Query timeout |
| `SQL_MAX_RESULT_ROWS` | `500` | Result row cap |
| `LANGGRAPH_RECURSION_LIMIT` | `16` | Graph step cap |
| `MAX_SQL_GENERATION_ATTEMPTS` | `3` | SQL retry limit |
| `LOG_LEVEL` | `INFO` | Logging level |

## How to run

Generate CSVs (if needed) and load SQLite, then start Streamlit from the project root:

```bash
python data/generate_data.py
python scripts/init_db.py
python -m streamlit run app.py
```

```powershell
.\.venv\Scripts\python.exe data/generate_data.py
.\.venv\Scripts\python.exe scripts/init_db.py

```

## Limitations

- Synthetic data only; not a production dealer system of record
- SQLite text dates; SQL must use SQLite date functions, not PostgreSQL
- Charts are heuristic (bar / line / pie) and skipped when the table is a poor fit
- Domain and SQL quality depend on the LLM; retries help but cannot fix every question
- Single-user local app; no auth, multi-tenancy, or warehouse scale
- Result sets are capped; very large “show everything” questions are truncated
